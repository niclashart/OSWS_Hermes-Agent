# FinVeriQA: Financial Research Agents for Question Answering: Routing, Retrieval, MCP Tool Use, and Provenance-Aware Evidence Verification

## Why — evidence

Quotes (Abstract, arXiv:2611.25071, score 8/10):
- "a shared-evidence check (the kind our validator performs) catches 35% of the errors, whereas a check against the original passage catches 77% (p=5.96×10⁻⁸); for DeepSeek-R1-8B, 68% vs. 90%."
- "when one figure in the shared evidence is corrupted, self-consistency stays confident (agreement 0.55 to 0.59 while accuracy falls from 0.50 to 0.00)"

Core transferable finding: answer verification must be **independent of the evidence the writer saw** — re-retrieve fresh evidence and check the answer against it, instead of checking against the context the answer was generated from. Strong quantitative gain (35% → 77% error catch), 7–8B models, consumer-GPU feasible.

## Proposal: RAG-NIMBF

### Design

Add an **independent-evidence verification metric** as a custom metric, not a chain component — keeps it benchmark-only:

- Config: `custom_metrics_enabled: true` + new key `verification_mode: shared | independent | none` (default `none`).
- `independent`: after generation, the retriever is re-queried with the question (+ answer entities) with the originally returned chunks filtered out; a judge LLM checks whether the answer is supported by the fresh chunks. Reports `verification_pass_rate` and `verified_accuracy` (accuracy among verified answers).
- Plugs into `benchmark/evaluation.py` metric registry alongside RAGAS/custom metrics; judge LLM defaults to the generator LLM (`llm_models`).

```python
# Draft generated by RAG Radar — untested, review before applying.
"""Independent-evidence answer verification (arXiv:2611.25071).

The paper shows a shared-evidence check catches 35% of corrupted-evidence
errors while a check against freshly retrieved (independent) passages
catches 77%. This module implements the independent check for benchmarks.
"""
from __future__ import annotations

from dataclasses import dataclass

from langchain_core.documents import Document


@dataclass
class VerificationResult:
    verified: bool
    judge_answer: str


VERIFY_PROMPT = (
    "Answer: {answer}\n\n"
    "Evidence (retrieved independently of the answer):\n{evidence}\n\n"
    "Is the answer supported by this evidence? Reply yes or no only."
)


def filter_seen(chunks: list[Document], seen: list[Document]) -> list[Document]:
    """Drop chunks already used for generation (by content identity)."""
    seen_texts = {d.page_content for d in seen}
    return [d for d in chunks if d.page_content not in seen_texts]


def verify_answer(
    question: str,
    answer: str,
    seen_chunks: list[Document],
    retrieve_fresh,   # callable(question, k) -> list[Document]
    judge_llm,        # langchain Runnable with .invoke(str) -> str
    fresh_k: int = 10,
) -> VerificationResult:
    """Check *answer* against evidence retrieved independently of it."""
    fresh = filter_seen(retrieve_fresh(question, fresh_k), seen_chunks)
    if not fresh:
        return VerificationResult(verified=False, judge_answer="no_evidence")
    evidence = "\n---\n".join(d.page_content for d in fresh[:fresh_k])
    reply = str(judge_llm.invoke(
        VERIFY_PROMPT.format(answer=answer, evidence=evidence)
    )).strip().lower()
    verified = reply.startswith("yes")
    return VerificationResult(verified=verified, judge_answer=reply)
```

## Proposal: Enterprise_RAG_Blueprint

Base branch: `feat/mcp-integration`@8d6aa7c (contains the current check chain and MCP integration; nothing equivalent on `main`).

### Design

Change `check_answer_with_second_llm` to support two modes via env `VERIFICATION_MODE` (`shared` = today's behaviour, `independent` = paper's recommendation, new default off to preserve behaviour):

- `independent`: the checker re-queries the retriever with the original question, filters chunks already used for the answer (by content), and judges the answer against the fresh context.
- New prompt `chain/prompts/rag_check_independent.j2` (same style as `rag_check.j2`).
