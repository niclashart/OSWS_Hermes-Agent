# Deal With It: On Better Schedules for Listwise Reranking

## Why — evidence

Quote (Abstract): "In existing schedules such as BlitzRank, dealing reduces repair calls from 59% of queries to 14%, improving latency with no significant change in quality."

## Proposal: RAG-NIMBF

### Design

Add an LLM listwise reranker as a new provider next to `huggingface:`:

- Config key stays `reranker_model`; new values `llm:<model-id>` (e.g. `llm:ollama:mistral-7b`) select the listwise provider.
- New module `benchmark/reranking_schedules.py` holds the permutation schedules. The paper's "dealing" schedule: candidates are dealt round-robin into sliding windows; windows are ranked by the LLM; results merged; a "repair" call (re-rank of a re-shuffled window) is only issued when windows overlap inconsistently — vs. sliding-window schedules that repair every overlap.
- Data flow: `retrieval.py` → `get_reranker()` → `LLMListwiseReranker.rerank()` → LLM via the existing provider stack (`benchmark/providers.py`), prompt template in `benchmark/prompt_templates/` style but local to the module (reranking prompt is provider-internal, not an experiment axis).
- Defaults: window size 20, dealing order, 1 repair round max, `reranker_top_k` reused unchanged.
- Tracing: `@observe(name="rerank")` like `CrossEncoderReranker`; additionally record `rerank_llm_calls` per query in the returned diagnostics-free way (log only, to keep the `Reranker` protocol intact).

```python
"""Draft generated by RAG Radar — untested, review before applying.

Candidate permutation schedules for LLM listwise reranking.

Implements the "dealing" schedule from arXiv:2611.22392 (round-robin dealing
of candidates into windows, repair only on inconsistent overlaps) and a
plain sliding-window baseline.
"""
from __future__ import annotations

from itertools import islice
from typing import Callable, Sequence

Schedule = Callable[[Sequence[int]], list[list[int]]]


def _windows(indices: Sequence[int], size: int, stride: int) -> list[list[int]]:
    out = []
    for start in range(0, len(indices), stride):
        window = list(islice(indices, start, start + size))
        if len(window) > 1:
            out.append(window)
        if start + size >= len(indices):
            break
    return out


def sliding_window(indices: Sequence[int], window_size: int = 20) -> list[list[int]]:
    """Baseline schedule: overlapping sliding windows (repair every overlap)."""
    stride = max(1, window_size // 2)
    return _windows(list(indices), window_size, stride)


def dealing(indices: Sequence[int], window_size: int = 20) -> list[list[int]]:
    """Round-robin dealing schedule (arXiv:2611.22392).

    Candidates are dealt round-robin into ``window_size`` piles, each pile is
    one LLM call; piles are disjoint, so no forced repair calls are needed.
    """
    piles: list[list[int]] = [[] for _ in range(min(window_size, max(1, len(indices))))]
    for i, idx in enumerate(indices):
        piles[i % len(piles)].append(idx)
    return [p for p in piles if len(p) > 1]


def repair_needed(window_ranks: Sequence[dict[int, int]]) -> bool:
    """True when two windows disagree on the relative order of shared items."""
    for a in range(len(window_ranks)):
        for b in range(a + 1, len(window_ranks)):
            shared = set(window_ranks[a]) & set(window_ranks[b])
            for x in shared:
                for y in shared:
                    if x < y and (window_ranks[a][x] < window_ranks[a][y])
                    != (window_ranks[b][x] < window_ranks[b][y]):
                        return True
    return False
```

class TestSchedules:
    def test_dealing_disjoint_piles(self):
        piles = dealing(range(50), window_size=5)
        flat = [i for p in piles for i in p]
        assert sorted(flat) == list(range(50))
        assert all(len(p) <= 5 for p in piles)

    def test_sliding_window_overlaps(self):
        windows = sliding_window(range(30), window_size=10)

        a = {1: 0, 2: 1}
